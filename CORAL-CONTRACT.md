## Rules

- `[AGENT-2]` Flag, don't guess: take the reversible option, mark it, surface it for human review.
- `[AGENT-4]` Never author an exception or an extension. A human decides and records.
- `[BOUND-2]` One request or trigger per slice, or a tightly-coupled pair, owned end to end.
- `[BOUND-3]` Use the boundary form the appendix fixes. Do not invent a new one.
- `[BOUND-5]` A scheduled/background trigger is a slice: observable outcome, overlap-safe, tested.
- `[BUCKET-1]` Do not create or expand `shared`/`common`/`utils`/`helpers`/`services`/`repository`/generic `models`.
- `[CLI-1]` Normal output goes to `stdout`. Errors and diagnostics go to `stderr`.
- `[CLI-2]` Failures return non-zero exit codes.
- `[CLI-3]` Read commands must support `--json` on `stdout`. Mutations may, and a mutation that does follows `[CLI-4]`.
- `[CLI-4]` Keep `--json` stable across patch releases, fully typed, and free of color, progress, or decoration.
- `[CLI-6]` No interactive prompts by default.
- `[CLI-8]` Exit `0` on success, `2` on invalid invocation, `1` on every other failure.
- `[CLI-9]` Use stable string `code`s on `stderr` for finer scripting precision, not a wider exit-code matrix.
- `[CLI-10]` Configure debug mode as one global flag at the root. Slices never configure tracing themselves.
- `[CLI-11]` Send trace output to `stderr`, stay quiet by default, and never pollute `--json` on `stdout`.
- `[COMMENT-1]` Comment only what the code does not show: a constraint, the reason for the current design, or behavior a competent reader would get wrong. Keep it short unless it warns. Do not record change history or how a decision was reached. Rename rather than comment what a function does. A doc comment that the language expects on an exported identifier is allowed, and states what a caller can rely on beyond the name and the signature. Document a published contract in full.
- `[COMPOSE-1]` Do not reach into another slice's internals. Depend on its published capability.
- `[COMPOSE-2]` Prefer injecting a capability through the root over a slice-to-slice import.
- `[COMPOSE-3]` A shared multi-step workflow is a candidate crosscut, not a `services` bucket.
- `[COMPOSE-4]` Read fan-in is a legitimate slice, provided it uses published capabilities only.
- `[CONC-1]` A slice holds no mutable state between triggers.
- `[CONC-2]` Every crosscut is explicitly shared-and-concurrency-safe or constructed per trigger.
- `[CONC-3]` Name the strategy where two triggers can write the same state: serialize, compare-and-set, or commute.
- `[CONC-4]` Scope a transaction to one trigger. Never hold it across an external call.
- `[CONFIG-1]` Resolve, validate, and inject configuration at the root as a crosscut.
- `[CONFIG-2]` No slice reads the environment, a config file, or a global settings object directly.
- `[CONFIG-3]` Validate every required setting at construction. Fail startup, not first use.
- `[CONFIG-4]` Read secrets only through the config crosscut. Never inline, log, or publish them.
- `[CONTRACT-1]` Keep the public contract stable, explicit, fully typed, and undecorated.
- `[CONTRACT-2]` Version public-contract changes per the app type's discipline.
- `[DEPS-1]` Receive only the dependencies and configuration values you consume, declared at your own boundary and supplied by composition. Never receive an application-wide container or configuration object you use only part of, and never obtain a dependency through service location. Bind each declared dependency deterministically to exactly one provider that satisfies your declared contract, keep explicit wiring identifiers from drifting, fail a missing or ambiguous binding before the consumer executes, in each supported configuration, and fail an incompatible binding before execution where reliable compatibility verification is available.
- `[DUP-2]` Do not extract on similarity alone. Similarity is not a shared concept.
- `[DUP-3]` Extract only to enforce an invariant or convention, provide named infrastructure, or clarify a real calculation.
- `[DUP-4]` Apply the Extraction Test before extracting.
- `[EFFECT-1]` Keep parsing, validation, normalization, calculation, and output shaping pure.
- `[EFFECT-2]` Keep side effects at the edges.
- `[EFFECT-4]` Do not extract a function only to make it pure or testable.
- `[ERR-1]` One small, stable, structured error model per app or published package: categories declared once for it, construction through that model, presentation owned by a boundary and never by a slice.
- `[ERR-2]` Raise through the declared taxonomy constructors of the slice's own app or published package, never an ad-hoc error type or a sibling unit's. Slices own their `code` strings.
- `[ERR-3]` Slices raise. The root renders, and so does a surface an app profile names as a presentation boundary. Nothing else renders.
- `[ERR-4]` Batch operations are all-or-nothing unless partial outcomes are reported explicitly.
- `[GROW-2]` Answer file growth by splitting inside the slice, never with a global abstraction.
- `[GROW-3]` Treat domain densification as a split signal, not a refactor-into-a-shared-core signal.
- `[IDEM-1]` The name signals the effect, and the implementation matches it.
- `[IDEM-2]` A read-named slice contains no write or mutation call, including a cache write.
- `[IDEM-3]` Do not change a non-idempotent operation's effect to an idempotent one without renaming it. A dedupe or idempotency key (`[IDEM-5]`) changes neither its effect nor its name.
- `[IDEM-4]` Never auto-retry a non-idempotent mutation.
- `[IDEM-5]` On an at-least-once platform, a mutating handler must be idempotent.
- `[IDEM-6]` Classify an unlisted verb by its effect and name it truthfully. Flag an unclear effect.
- `[MODEL-1]` Every unit of code is a slice, a crosscut, an adapter, the composition root, or a published contract.
- `[MODEL-2]` Name every package for the capability or concern it owns, never for its technical role.
- `[MODEL-4]` An adapter implements a slice-declared port: infrastructure only, arrow inward, wired by the root, no behavior.
- `[OBS-2]` Configure observability at the root, and emit through the injected crosscut.
- `[OBS-3]` Keep diagnostics off the machine-readable contract channel.
- `[ROOT-1]` Keep the root thin: register, construct, inject, bootstrap. No business logic.
- `[ROOT-2]` The root imports no slice-internal module and makes no state-access call. Importing a crosscut, an adapter, or a slice's entry point to wire it is not a violation.
- `[SCOPE-3]` When features converge on one dense concept, give it its own app behind a published contract.
- `[STATE-1]` Keep state-access logic local to the slice that needs it.
- `[STATE-2]` Do not create a shared repository or data-access layer.
- `[STATE-4]` The slice that computes derived state owns it. Write it from a set- or event-named handler.
- `[STATE-5]` One owning feature package per table/file/bucket, schema defined once inside it. Siblings reach it directly, and outsiders go through a published capability.
- `[STATE-6]` A cache is never a source of truth. Every read path must be correct with it empty.
- `[STATE-7]` Name the cache's invalidation strategy: TTL, write-through, or event-driven.
- `[STRUCT-1]` Colocate tests, or mirror the package structure where colocation is impossible.
- `[STRUCT-2]` Put slices in concrete, domain-oriented feature packages. The package owns its capability's state.
- `[STRUCT-3]` Keep root-level crosscuts rare and precisely named.
- `[TEST-1]` Behavior-first: exercise the entry point, assert the observable contract, real or realistic temporary infra, minimal mocking.
- `[TEST-2]` Prefer integration and end-to-end tests over isolated unit tests.
- `[TEST-3]` Unit tests are a scalpel. Never duplicate integration coverage, and never extract only to test.
- `[TEST-4]` Assert contract, errors, idempotency, transactions, authorization, and diagnostics where relevant.
- `[TRUST-1]` Validate and authorize untrusted input at the boundary.
- `[TRUST-2]` State the app's trust boundary explicitly, however minimal.
- `[VER-3]` State the Coral version a project targets, and audit against that version.
- `[VER-5]` Record exceptions and extensions in `CORAL.md` as machine-readable entries naming a rule ID and a scoped path.
- `[VER-6]` Declare in `CORAL.md` which non-kernel Coral scopes the project adopts, and at which scales.
- `[XCUT-1]` Promote to a crosscut only when it is genuinely cross-cutting AND enforces a must-not-diverge invariant.
- `[XCUT-2]` Give every crosscut a precise domain or infrastructure name.
- `[XCUT-3]` Consume a crosscut through its published surface, never its internals. Inject one that holds configuration, a connection, or per-trigger state.
- `[XCUT-5]` A domain entity may be a crosscut only as type + invariants, never its queries or storage.
