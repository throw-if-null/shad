# Decisions

Append-only. One row per decision. A reversed decision gets a new row that names the row it
supersedes.

| Date | Decision | Reason | Decided by | Revisit when |
|---|---|---|---|---|
| 2026-11-01 | A commit under the maintainer's identity is the maintainer's decision, including code an agent generates in a session the maintainer directs. An agent that works without that direction commits under its own identity, and its commits follow `[AGENT-2]` and `[AGENT-4]`. No commit carries generic tool attribution. | The commit identity names the person accountable for the decision. A separate identity makes autonomous work auditable. Rejected: agent attribution on commits from a directed session, because the maintainer made those decisions; generic tool attribution, because it names no one who decided. | Mirza Merdovic | An autonomous agent starts work in shad, or Coral states a different provenance requirement. |
| 2026-11-04 | The migration to Coral lands in this order: the test infrastructure and the behavior tests of every command, then one stream of structural pull requests (error model, root and presentation, named crosscuts, configuration), then one task per command group, then documentation and the adherence record. | The published contract (exit codes, `stderr` codes, `--json`) changes once, and no slice is migrated twice. Rejected: a minimal core followed by per-command migration, because the contract would move per command and a one-category default would stand for the duration; a strangler with no core task, because two rendering paths and two exit-code mappings would coexist. | Mirza Merdovic | The structural stream cannot land as reviewable pull requests. |
| 2026-11-04 | The error model is the `[ERR-5]` taxonomy: `usage`, `validation`, `not_found`, `conflict`, `infrastructure`, `internal`. The root maps `usage` to exit 2 and every other category to exit 1, prints one undecorated line `<code>: <message>` on `stderr`, and prints the traceback under `--debug`. An interrupt exits 130. A command that hands the terminal to tmux returns tmux's exit status. | The six categories fit every failure shad raises, and the CLI appendix's example uses them. Rejected: four categories, because a missing todo key would read as a validation error; keeping the `✗` marker, because a script would strip it. | Mirza Merdovic | A failure fits no category, or Coral changes `[CLI-8]`. |
| 2026-11-03 | Interactive forms are opt-in by flag. `--pick` opens a picker (`sessions save`, `sessions stop`, `projects <name>`), `--resume [ID]` resumes a conversation, `--wizard` runs the `init` questions, `--yes` applies the `git sync` deletions. Without the flag: `projects <name>` opens a new conversation; `sessions save` and `stop` take session names or `--all`; `init` takes `--path`, `--group`, `--key`, `--session`; `git sync` reports the deletions and deletes nothing; `todo add` without a title opens the editor and reopens a rejected draft with the error in its `#` lines. | A script gets the behavior a terminal gets (`[CLI-6]`, `[CLI-7]`). Rejected: one `[CLI-6]` exception per path; a terminal check deciding the default. | Mirza Merdovic | Coral permits a prompt by default on a terminal. |
| 2026-11-03 | A picker asked for with `--pick` and no terminal is an `infrastructure` failure with code `no_terminal`, exit 1. A deliberate cancel (`q`, `Esc`) exits 0 and changes nothing. | A script must tell a missing terminal from a cancel. Rejected: treating a missing terminal as a cancel. | Mirza Merdovic | A command needs a terminal for something other than a picker. |
| 2026-11-03 | A fresh open never kills an existing tmux session. A fresh target always gets a session name that does not exist, and the opencode fresh key cannot collide. | The kill branch was reachable only when two opens of one project landed in the same second, and its effect was destructive. Rejected: keeping the kill and documenting it. | Mirza Merdovic | A harness needs a fixed session name for a fresh conversation. |
| 2026-11-04 | `git sync`: fetch, prune and fast-forward always run; only the deletions need `--yes`; a run with one failed project exits 1; every exception a project raises is caught per project and reported in that project's outcome, with its traceback under `--debug`. | A pruned remote-tracking ref is the evidence that a gone-upstream branch was pushed, and a dry run must not consume it. One bad project must not abort the rest. Rejected: gating prune and fast-forward behind `--yes`; exit 0 on a partial failure; letting an unexpected exception abort the run. | Mirza Merdovic | Coral states a different partial-mode exit code, or a project needs an all-or-nothing sync. |
| 2026-11-04 | `git panel` fetches on open and on `r`, never prunes, and changes nothing else. Its help says so. | A pruned remote-tracking ref deletes the reflog that `git sync` relies on. Rejected: no fetch by default, because the counts would be stale. | Mirza Merdovic | The sync stops relying on the reflog. |
| 2026-11-04 | Todo writes are last-writer-wins. | One user on one machine; a lost status change is visible in the panel within its one-second poll; an `$EDITOR` write cannot take part in a compare-and-set. Rejected: compare-and-set on the panel's status write. | Mirza Merdovic | Two writers run unattended. |
| 2026-11-04 | Each todo, sessions and config action lists and parses the files it reads. A package's store module keeps only the directory layout and the write mechanics, and the exclusive create and the atomic replace are one root crosscut. No `[STATE-1]` exception is recorded. | `[STATE-1]` keeps queries in the slice, and the accepted Coral text for file-backed stores says the same. Rejected: a `[STATE-1]` exception per store module. | Mirza Merdovic | Coral permits a package-scoped read module. |
| 2026-11-04 | Command names stay: `shad projects <name>` opens, `shad projects` lists, `shad projects <name> status` reads, `shad todo status KEY STATUS` sets. The help states each effect. | A rename breaks every existing invocation and the completion script for no caller benefit. Rejected: `projects open`, `projects list`, `projects status`, `todo set-status`. | Mirza Merdovic | A second verbless command is added, or a read and a write share one verb inside one command group. |
| 2026-11-04 | A capability package keeps its crosscut at the package root and one sub-package per action, and outsiders import only what its `__init__.py` publishes: `git/` holds `run`, `refs`, `discover`, `model` plus `sync/` and `panel/`; `config/` holds `schema`, `load`, `store` plus the eight actions. A root-level module is a crosscut named for its concern. | A root crosscut and an action package cannot share one Python name. The pattern mirrors `todo/` and `sessions/`. Rejected: root crosscuts with renamed command packages (`gitsync`, `gitpanel`, `settings`). | Mirza Merdovic | A package's crosscut gains a consumer that the published surface cannot serve. |
| 2026-11-04 | An acceptance criterion lives in the docstring of the test that asserts it, in the Feature/Boundary/Criterion/Given/When/Then format of the behavioral verification protocol, and the test is named after the criterion. | Both halves of a criterion land in one file and one pull request. Rejected: a criteria document beside each slice. | Mirza Merdovic | A criterion needs a reader who does not read tests. |
| 2026-11-21 | A command declares each dependency it uses as a keyword-only parameter of `run`, named from `wiring.PROVIDED`, and the root supplies those and nothing else. A command or a module it calls across a unit boundary receives the configuration values it reads, not the whole `Config`. The `Deps` object is removed. | Coral 0.10.0 adds the kernel rule `[DEPS-1]`, and every command received the whole `Deps`. Supplying by declared name keeps `cli.py` free of action names and constructs the config only for a command that declares it. Rejected: a `CORAL.md` exception, because one scoped to all of `src/shad` excuses the rule (`[VER-5]`); explicit per-command wiring in `cli.py`, because the root would name every action. | Mirza Merdovic | Coral changes `[DEPS-1]`, or a dependency cannot be supplied by name. |
| 2026-11-21 | The 2026-11-21 [DEPS-1] decision holds under Coral 0.11.0. Dependencies are still matched by parameter name. PROVIDED is built from Supply, and `test_wiring.py` checks every registered command's declared names and types against it. | 0.11.0 requires deterministic, verified binding. Its own example shows name-based wiring as conforming when a check verifies it. Rejected: wiring each command explicitly in cli.py, because the root would have to name every action. | Mirza Merdovic | Coral changes [DEPS-1] again, or a provider type cannot be compared with an annotation, such as a non-runtime Protocol. |
